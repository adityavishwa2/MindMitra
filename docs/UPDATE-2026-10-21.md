# Administration and approval update — 21 October 2026

The admin home now leads with Review papers and Review videos, each with a pending count. Four main navigation links replace the crowded row; less frequent tools and statistics are collapsed. Paper/video queues default to awaiting approval, use clear review buttons and readable status labels. Video review is paginated so older pending lessons are not displaced by reviewed records.

Paper review has numbered permission, question and publication steps; a checklist identifies invalid fields, missing permission and remaining verified answer references. It can jump to the first unfinished answer. Finish review and publish is visible from every question. The older unscored publication/rejection controls are grouped under Other decisions. Source/hash metadata is collapsed. Prepared JSON imports and existing papers remain accessible via the library, with published records separated from pending verification. Existing permission values initialize correctly in the authorization editor; permission options now submit explicit enum values instead of translated labels with whitespace, fixing rejected authorization updates; correction payloads preserve source regions.

Video review uses explicit typed decision handlers, removing dependence on native submitter events and browser constraint-validation bubbles. Controlled checks/notes show completion counts, minimum note length and blockers before the buttons. Results and errors appear at the top of the decision controls. Own-upload restrictions are explained in the queue and review page. Independent review, all content checks, origin checks, authorization, audit records and private-media protections remain enforced on the server.

No new database migrations are introduced. Follow [admin review](admin-review.md) to update and find the approval controls. The original scanned-paper support, 20 MB PDF limit and Windows media-tool setup are retained. This update does not claim an automatic nudity or educational-value classifier; video publication still requires full human review.

## PDF-only intake update

The admin/community upload forms now ask only for a PDF. No source URL, alias, exam, year or permission attestation is required at upload. Filename/early PDF text supply metadata suggestions; uncertain exams go to Uploaded PYQ and missing years receive an explicit placeholder warning. Review can correct the exam/year/title, then publication adds the approved paper directly to the selected PYQ collection.

Exact repeats reuse the existing submission and preserve feedback/publication; failed conversions can retry. Public aliases are decoupled from uploads. Private submission IDs are not exposed to other members. Uploaded sources use a checksum-bound URN instead of a fabricated web URL. Approval, answer-key verification, source comparison and reuse authorization remain required. See [PDF-only upload](pdf-only-upload.md). No new migration is introduced.

## CBT and Shorts update

Compact question/option editing replaces the tall remove-button rows. Answer references are no longer requested or required. Original PDFs use private full-page previews; scanned regions get local OCR transcription with retry/editing. Approved questions publish as native CBT text/options, with source regions retained in review rather than copied to new published questions. Placeholder scans are blocked until corrected. Existing attempt snapshots are preserved.

Learn Shorts now uses vertical scroll snap, muted autoplay for the visible player, sound/pause controls, persistent likes and responsive layouts. Topic/objective fields are omitted from video upload. The allowance is 20 videos per user per rolling 24 hours, with no separate pending cap; 25 MB/three-minute file limits remain. Apply the new VideoLike migration. See [CBT and Shorts](cbt-and-shorts.md).
