# Authentication, security, and privacy

Google OAuth is handled by NextAuth v4 and its supported Google provider: OpenID discovery, verified email, PKCE/state, CSRF-protected sign-in, and database sessions. The provider requests only `openid email profile`. Redirect validation uses the framework defaults. No arbitrary account is promoted to administrator. Use `npm run admin:grant -- email` on a trusted server for an already registered user.

The local environment generates `NEXTAUTH_SECRET`; Google credentials are absent until the owner configures them. Keep Google OAuth in testing mode with selected test accounts until release gates are satisfied. A real Google sign-in, consent-screen verification, and production callback cannot be validated without those account-specific credentials and domains. Test-only sessions are inserted by browser-test setup into a separate database; there is no app route to mint them.

Private reads use the server session. Writes validate the same-origin Origin header against `NEXTAUTH_URL`, load the user from the database, validate with Zod, enforce record ownership, and repeat ADMIN authorization for admin operations. The database implements a 120-writes/minute/user limit. Concurrent finalized answers and submissions use serializable transactions and reject conflicting writes; a client can retry a conflict. Anonymous OAuth traffic should additionally be rate-limited at the hosting edge for a public deployment.

Question text is ordinary escaped React content. Only KaTeX-produced markup is injected, with `trust:false`. User content is never interpreted as HTML. Source links require HTTPS. No arbitrary URL is fetched by the server, and YouTube embeds accept only an eleven-character video ID. JSON imports are capped at 2 MB and PDFs are privately stored and processed by a queued worker using bounded native text/OCR commands without a shell. See [conversion limits and worker hosting](pdf-conversion.md). Antivirus scanning and per-document container isolation are not implemented.

Headers restrict framing, object embedding, MIME sniffing, referrers, camera, microphone, and geolocation. The application CSP allows the Next.js bootstrap and inline styles, local assets, Google profile images, and privacy-enhanced YouTube frames. It is not a nonce-based strict CSP. HTTPS and TLS termination belong to the hosting configuration. Do not disable certificate validation for PostgreSQL or provider connections.

Students can export selected account activity without OAuth credentials and delete their cascading private records. Google tokens and session records are never exported. Audit records retain actor IDs for content accountability; define and implement an operator-approved retention/anonymization schedule before launch. Device-held unsynced quiz responses should be cleared on shared devices; account deletion cannot erase backups or copies exported earlier. The service worker caches only a public offline page and original icon assets, never private pages, APIs, or exam content.

No unrestricted messaging, public student profiles, third-party analytics tracking, or mandatory paid AI services exist. The optional public-alias leaderboard only credits approved published contributions. Legal/privacy text is a draft. Parental consent, age-appropriate enrollment, operator contact details, retention enforcement, incident monitoring, penetration testing, and independent legal review are release requirements that this implementation does not yet satisfy. Do not describe it as production-audited or open public registration until those are completed.

## Dependency advisory status

The production dependency audit reports zero known advisories at validation time. The full audit also includes five high-severity findings in the ESLint-only dependency chain (`eslint-config-next` → `fast-glob` → `micromatch` → `braces`, GHSA-vfj7-8cjw-p6xm). The available braces release is 3.0.3 and no patched compatible release was available in this session. This parser runs in development lint tooling, not application request handling. Do not feed untrusted arbitrary glob patterns to that tooling; revisit the advisory when upstream publishes a patch. The application was not downgraded to an incompatible framework/configuration to suppress the report.

Educational video uploads are quarantined in private database storage. Server checks enforce membership/ownership, educational metadata, file/codec/duration/size limits, quotas and full independent administrator approval; native media checks do not recognize nudity or classify educational relevance. Only approved media is available to other members. Reports and revocation hide it from new requests. Camera/microphone access is permitted only on the recorder document, after browser consent. See [video operation and limitations](videos.md).

Upload requests share a canonical-origin validator. When NEXTAUTH_URL is local or absent, the actual loopback HTTP target is also accepted so a local hostname/port mismatch does not break uploads. Arbitrary remote origins, missing/null origins and forged forwarded-host headers are rejected. Public deployment origins must match NEXTAUTH_URL. PDF bodies are capped at 20 MB (plus bounded multipart metadata); JSON files remain capped at 2 MB.
