# Architecture and database

Next.js server components query PostgreSQL through Prisma. Client components own transient quiz/game state and call authenticated route handlers for writes. Google-only NextAuth uses the Prisma adapter and database sessions. The student route-group layout requires authentication; the admin layout additionally requires a server-loaded ADMIN role. Every write repeats authorization. Client navigation never grants permission.

`app/api/[...path]/route.ts` dispatches validated operations. This is appropriate for this initial scope; split it into domain route modules when adding more operations. `lib/practice.ts` owns paper selection and finalization; `lib/scoring.ts` is a pure deterministic scorer; `lib/analytics.ts` derives reports from actual associations. There are no fabricated counters or sample student records in the main database.

## Relational design

- Identity: User, Account, Session, VerificationToken. User stores onboarding preferences and ordered examination goals.
- Catalog/provenance: Authority → Exam → Paper → Question. Paper identity is unique by exam/year/stage/shift. SourceDocument deduplicates source URL plus SHA-256 and records reuse evidence.
- Keys/reviews: AnswerKey has append-only question/version identity. VerificationReview and AuditLog retain review decisions and high-impact content changes.
- Practice: PracticeSession → SessionQuestion and StudentAnswer. SessionQuestion snapshots source text/options and the answer-key version at launch. Answers are unique by session/question. Serializable transactions protect finalization and concurrent answer writes. Repeated submission returns the stored result.
- Private activity: Bookmark, StudyTask, GameSession, VideoBookmark, WatchSession, VideoReport. All user-owned rows reference a User and cascade on deletion.
- Operations: ImportJob records successful ingestion; RateBucket implements a database-shared per-user write limit and expired-bucket cleanup.

Indexes support examination inventory, user practice history, private tasks, and games. Database constraints prevent duplicated paper shifts and question numbering. There is no all-history completeness claim: current inventory is the only denominator.

## Publication boundary

A paper can launch practice only if `status=PUBLISHED`, its source is `AUTHORIZED`, and verified questions exist. Imports enter `AWAITING_VERIFICATION`; human approval is necessary. Pending and denied source permissions block publication. Revoking source rights also withdraws its published papers. Disputed/unavailable answer keys remain explicitly unscored. Descriptive responses are saved for self-assessment.

Practice pages send public question snapshots and the student’s own responses to the client, excluding answer keys. Result pages reveal the snapshotted key only after submission. Quiz state is keyed by session ID in device storage for reconnect recovery, and is removed on successful submission. No server query permits another user’s session or answer to be changed.

## Runtime and migrations

Prisma 6.19 uses the JavaScript client engine with `@prisma/adapter-pg`; the cloud’s restricted egress initially blocked native engine downloads. The Prisma JavaScript migration adapter then failed on PostgreSQL’s `name` type. `scripts/migrate.ts` executes committed Prisma-style SQL migrations transactionally, records their SHA-256 in `_prisma_migrations`, holds a PostgreSQL advisory lock, and rejects changed/incomplete applied migrations. It never silently resets a database.

The initial SQL was generated by `prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script`; later migrations are reviewed SQL alongside the schema. For new changes, generate/review a diff using Prisma in a supported migration environment, commit a new migration directory, then run `npm run db:migrate`. Do not edit previously applied SQL. Driver-adapter migration mode is experimental; test upgrades on a disposable database.

A scoped `deepmerge-ts` override to version 8 addresses GHSA-ggr8-5vv4-36mx in Prisma’s configuration tooling. Generation, migrations, builds, and application tests are exercised with it. Keep this override under review when upgrading Prisma.
