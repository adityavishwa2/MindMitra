# MindMitra update — 19 October 2026

The updated source preserves the newer admin PDF inbox features missing from the uploaded ZIP.

## Included

PDF uploads automatically enter a persistent conversion queue. Embedded text is extracted; scanned pages use OCR. Supported numbered MCQs become editable import JSON with original page references and PDF checksums. The review screen shows progress, warnings, extracted text, errors and administrator retry. Interrupted workers recover their work. Both `npm run dev` and `npm run start` run the worker with the application.

English OCR is the default. Install Hindi language data and set `PDF_OCR_LANGUAGES=eng+hin` for Hindi scans. The supplied Dockerfile includes both language packs. `npm run doctor` checks required tools, the database migration and authentication configuration without printing credentials.

Automatic conversion prepares drafts. Review every question and option, classify subjects, set actual scoring and verify permission and answer references before publishing. Answers are never guessed. Complex layouts, diagrams and unsupported formats require manual correction; extracted text remains available.

## Upgrade

Back up the database, extract the updated source into a new folder and keep your existing private `.env` beside `package.json`. Keep the existing database. Install Node.js 22/24 LTS, Poppler and Tesseract, then stop the old application and run:

```sh
npm ci
npm run db:migrate
npm run doctor
npm run build
npm run start
```

Fix any configuration issues reported by the readiness command. For a fresh local installation, follow README's `npm run setup:local` instructions. Detailed Windows, macOS, Linux, container and worker-hosting instructions are in [PDF conversion](pdf-conversion.md).

Upload at **Admin → Import papers**, open the PDF inbox record and review the automatically generated draft. Limits remain 2 MB per upload and 80 pages. A serverless web deployment needs a separately hosted persistent worker. No private credentials or database files are included in the source archive.

## Video creation update

Learn Shorts now has **Create a learning video** with a distinct animated hover/focus button. Record with the browser camera/microphone or upload MP4/WebM (25 MB, up to three minutes). Install FFmpeg/FFprobe on the web server, then apply all migrations and rebuild. The Dockerfile includes these tools.

Uploads stay private until a different administrator watches the full video and confirms its educational purpose, absence of nudity/sexual content, absence of abuse/violence and absence of promotions. Only approved videos enter the native player. Reports hide videos pending another review; administrators can reject or revoke them. Existing external-video approvals are hidden until re-reviewed under the new policy. This uses mandatory human moderation, not automatic nudity detection. See [video setup and moderation](videos.md).

The video update passed TypeScript, ESLint, the production build, all 28 domain/conversion/policy tests and all 15 browser/database tests. ## Quiz saving and recovery fixes

- Submitting while an answer is uploading now waits for that upload and any newer selections before finalizing. Responses for older edits cannot clear newer pending answers.
- Reconnect caches are validated against the session's question types and options. Malformed JSON, null/array caches, removed questions, duplicate or out-of-range selections are ignored instead of crashing practice or repeatedly submitting invalid data.
- Browser storage failures no longer stop answer input or successful submission. When offline storage is unavailable, the app tells students to keep the page open until syncing succeeds.
- Repeated submit clicks are guarded, and answer edits are frozen during finalization.

Timed exams still accept only answers received within the server deadline. Offline answers cannot be backdated after time expires.

## PDF/video request origins and 20 MB PDFs

All application write routes now share the same origin validator. It accepts the configured canonical origin, plus the actual HTTP loopback target (`localhost`, `127.0.0.1`, or IPv6 loopback) when NEXTAUTH_URL is local or absent. This fixes local address/port mismatches without accepting external origins or trusting forwarded-host headers. Public deployments must still configure NEXTAUTH_URL correctly. Rejected requests now explain which setting to check.

PDF uploads support **20,000,000 bytes (20 MB)** in the form, streaming API and conversion worker. JSON uploads/review payloads retain their 2 MB limits. Conversion retains its 80-page and 2 MB extracted-text limits. Video uploads remain limited to 25 MB. No new database migration is required for this update.

For Windows, preserve your existing `.env` and database, then run these commands inside the extracted `MindMitra` folder:

```powershell
npm.cmd ci
npm.cmd run db:generate
npm.cmd run dev
```

For the default local address, set `NEXTAUTH_URL=http://localhost:3000` in `.env`, restart the app, and open exactly `http://localhost:3000`. If using a different port or a public domain, use that full origin instead. The Google OAuth client must have the matching `/api/auth/callback/google` redirect URI. Do not post secrets when asking for configuration help.

## Visual question and answer-key review

PDF and JSON submissions now have a visual question editor. Reviewers can read/edit question text and options, choose MCQ/MSQ keys, add references, classify subjects, set scoring and source permission, and add missing questions. Raw JSON is optional and kept in sync with form edits. Save review draft persists valid private work; Approve and publish stores the reviewed payload and exposes the paper in exam preparation. Student practice and scoring use the selected keys. See `docs/review-editor.md`.

Conversions with parsing omissions, ambiguous option ordering or duplicate numbers now finish as NEEDS_REVIEW even when some questions were recovered. Existing drafts still need comparison with the original source. This update does not reconstruct unreadable source questions or infer reliable answer keys from damaged OCR text.

## Scanned question cards and answer feedback

The supplied GS Series D PDF now converts to 100 original-image question cards using a checksum-matched coordinate profile. No answers are inferred from handwriting. Other scanned layouts use local deskew/column OCR and require crop/count review. A shared answer-key reference, Save answer & next and Finish review and publish support answer feedback without JSON editing. Practice and results display the original image and use the verified key.

Apply both new migrations with `npm.cmd run db:migrate`: question source regions and retained authorized source PDFs. Existing PDF submissions can be reconverted; this replaces their old drafts after confirmation. Keep `.env` and the database. See [scanned papers](scanned-papers.md).
